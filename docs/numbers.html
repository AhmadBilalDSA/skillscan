Measured results

These are SkillScan's own numbers, published as measured — including the families where the rates are poor. They come from the project's README; the full methodology, counting rules and caveats are in the repo's benchmark document.

The corpus and the run

The corpus is MaliciousSkillBench — 9,740 labelled skills: 7,505 malicious, 2,235 benign. First run 2026-11-11 with SkillScan v0.6.0; re-run 2026-11-15 with the current tree (64 deterministic rules) — the figures below are that run, made with the deterministic offline mode only (no --llm). Malicious skills were scanned as complete extracted folders; benign skills are shipped by the benchmark as frozen text, so each was scanned as a single SKILL.md folder. Nothing was executed — folders were read as text only.

What moved in the 2026-11-15 run

One change moved the numbers: the INJECTION_EXECUTION promotion. 297 malicious skills moved from CAUTION to BLOCK — every one a completed staging chain (a file written to a fixed temp path and tied to execution in the same file). That took BLOCK from 45.8% to 49.8% at zero measured false-BLOCK cost on either benign corpus.

The same day, a fix wave tightened three over-broad rules to require the evidence their names claim. The trade was 34 explained BLOCK losses against 27 gains — net BLOCK 3,696 → 3,689 (49.7%), and benign CAUTIONs 557 → 551. Correctness over coverage: a headline rate bought with other people's false alarms is not a rate worth printing.

What was measured and refused

Eight CAUTION combinations were measured as candidate promotions to BLOCK. Only one shipped. The other seven were not promoted — each has a legitimate twin the scanner cannot tell apart at line level. Two examples, priced and closed:

  • The broad capability pairs (network access + subprocess; chmod + subprocess) were priced against code-bearing benign skills: they trip 8 and 9 held-out honest tools respectively — checksum-verified installers, permission fixers, freshness reporters — so they stay at CAUTION permanently.
  • A shell-string narrowing of those pairs was built and measured at +147 malicious CAUTION → BLOCK, then parked after adversarial review built honest shell-string users (build runners, an ffmpeg media tool, a git-hook installer, localhost test harnesses, an rsync backup) that it blocked wholesale. It does not ship.

Cross-file dataflow was scoped the same way: a census of the 239 code-bearing malicious skills that PASS found the chain halves absent, not unjoined — honest yield 0 — so the engine is parked, not planned.

The misses, stated plainly

  • Most misses are prose-only skills. 1,305 malicious skills still PASS; 887 of them are a single SKILL.md with no code at all. Among pure instruction-manipulation skills the BLOCK rate is 8.8%, and pure output manipulation is ~2% — deterministic rules see behaviour shapes, not meaning.
  • The benign side is prose-only (see above), so the false-BLOCK figure measures prose-triggered false alarms, not code-triggered ones. That asymmetry is part of the corpus, and it is disclosed rather than smoothed over.
  • Against 25 techniques from four published audits of real malicious skills and MCP servers, the repo's coverage map counts 4 covered, 13 partial, 8 gap. SkillScan is strong on the code-shaped half of those audits and weak on the language-shaped half — several of which no static folder scanner can see.

The wider truth on false blocks

The zero-false-BLOCK figure above is exact for the corpus it names. Because that corpus ships benign skills as prose only, a second, code-bearing benign set was built: 392 hand-written benign skills with real code. There the scanner stands at 49 BLOCK / 286 CAUTION / 57 PASS. Every remaining BLOCK is a stated stance, not a defect — any persistence install blocks, disclosed or not (22), and uploads to the user's own cloud still match the exfiltration shape (16). Three defect groups the set exposed (an SSH permission fixer, plain curl downloads, a skill's own temp-folder cleanup) were fixed in the 2026-11-15 fix wave.

The optional LLM mode, measured so far

The deterministic figures above do not change with --llm; the README's Modes section reports the live-model measurements separately. On the benchmark's output-manipulation family, a current-model judge lifts BLOCK+CAUTION from 28.9% to 54.6% with zero false BLOCKs on 280 benign skills. Weak free-tier judges lift the held-out malicious set materially (Gemini Flash-Lite 37.0% → 53.4%; the default Qwen 34.1% → 43.2%). Gemini Flash-Lite also reviewed 258 of 259 held-out benign skills with 0 false BLOCKs and 0 added CAUTIONs. The default Qwen's benign-set run was stopped by its free-tier limit after 2 calls, so that preset's benign rate at corpus scale remains unmeasured — the README labels it that way, and so does this page.
