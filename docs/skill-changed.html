Did this skill change since I installed it?

A skill can be safe on the day you install it and silently different a week later. SkillScan by RakTikoo has a change watch for exactly that question: --pin records a fingerprint of a scanned folder, and --check-pin later re-scans and reports a plain diff of what changed.

1. Pin the skill when you install it

python3 -m skillscan <path-to-skill-folder> --pin pin.json

The pin records a hash of every entry in the folder, the verdict, the findings, and the rule-set version. A real run looks like this:

Pinned 3 entries from .../my-skill (verdict PASS) -> pin.json

The fingerprint covers every entry — regular files of every type (not only the ones the scanner reads, because a change can arrive as a file the scanner does not parse), directories, special files, the permission bits on files, and symlinks. Nothing is skipped, not even .git or __pycache__.

Keep the pin outside the folder it fingerprints: a pin inside it can be rewritten by the same hand that changed the folder, and --pin warns when asked to write one there.

2. Check it later

python3 -m skillscan <path-to-skill-folder> --check-pin pin.json

If nothing changed, the answer is one line and exit code 0:

No changes: every entry in the folder is identical to the pin (pin.json), and the scan result is the same (verdict PASS).

If files changed but the scan result did not, the changed entries are named and the exit code is 1:

Files changed on disk — same scan result (verdict and findings identical).
Added files (1):
  + notes.txt

Findings are compared by what they say, not by line number: inserting a comment above a flagged line is a files-changed (1), not a scan-result change.

Check-pin exit codes

Exit codeMeaning
0No entry changed. (A rule-set version difference alone is reported, not failed — the scanner changed, not the skill.)
1Files changed, but the scan result (verdict + findings) is identical.
2The scan result changed — review before trusting this skill again.
3The pin cannot be used.

Two honest limits

  • An edit that changes neither a finding's rule, evidence, nor count on an already-flagged file (for example swapping the host on an already-flagged network line) also lands at exit 1, with the file named — read the named files.
  • A skill that writes runtime state (logs, caches) inside its own folder will show those as changed entries.
